# 应用仓库页面层级收敛设计

## 背景

当前应用仓库页面同时展示标题卡片、帮助横幅、搜索工具栏、同步统计、仓库列表和多种操作入口。信息本身完整，但默认层级过多，用户难以快速判断“仓库是否可用”和“下一步要做什么”。

KubeSphere v4.3 的首页采用任务入口和单一内容面的方式，能够降低首屏认知负担。本次设计提取这一原则，但不迁移 v4.3/LuBan 的路由、运行时或企业版接口。

## 目标

- 将应用仓库页面的默认结构收敛为“标题 → 工具栏 → 列表”。
- 保留添加、刷新等高频操作，避免优化后操作入口消失。
- 将同步诊断、Events、完整错误和低频操作移动到详情页/抽屉。
- 继续复用现有 HTTPS/OCI、手动同步、定时同步和全量校验 API。
- 不改变仓库权限、凭据引用和敏感信息脱敏规则。
- 在桌面和小屏下都保持可读、可操作，不通过固定宽度制造横向滚动。

## 非目标

- 不重写 Repository Controller 或同步协议。
- 不新增后端任务系统、WebSocket 或跨页面推送。
- 不把 v4.3 的 LuBan UI、4.2+ API、License 或企业扩展能力迁移到当前版本。
- 不改变“立即同步异步执行”和“定时同步按 syncPeriod 执行”的语义。

## 目标信息架构

```text
应用仓库
  简短说明
  └─ 工具栏：搜索 | 刷新 | 更多设置 | 添加
       └─ 仓库列表
            └─ 行菜单：查看详情 | 立即同步 | 全量校验(OCI) | 编辑 | 删除
                 └─ 详情页/抽屉：同步诊断 | Events | 凭据摘要 | 操作记录
```

### 页面标题区

- 保留标题和一句用途说明。
- 帮助内容默认折叠为单行提示，支持展开和关闭；关闭后不占用列表首屏空间。
- 不在标题区放置多个相互竞争的主按钮。

### 工具栏

- 搜索保持左侧并占据主要宽度。
- 刷新保留为图标按钮，并提供可访问名称。
- 设置、批量操作等低频入口收纳到更多菜单。
- 添加仓库保留为唯一主按钮。

### 列表行

默认只展示：

- 名称和图标。
- 状态：成功、同步中、失败、过期。
- 一行同步摘要：耗时、有效版本数或脱敏错误摘要。
- 仓库 URL 和类型。
- 更多操作菜单。

完整请求数、缓存命中、跳过 Artifact、Events 和错误堆栈不在列表行展开。

### 详情页/抽屉

详情分为两个层次：

1. 概览：仓库地址、类型、当前状态、最近同步时间、有效版本数、凭据是否已配置。
2. 诊断：同步生命周期、OCI 统计、脱敏错误、Kubernetes Events 和重试入口。

凭据只显示“已配置/未配置”和非敏感名称摘要，不能显示 Secret 内容、用户名密码或 Token。

## 操作语义

| 操作 | 作用域 | 展示位置 | 说明 |
| --- | --- | --- | --- |
| 添加 | 页面 | 工具栏主按钮 | 打开现有添加表单 |
| 刷新 | 页面 | 工具栏图标 | 重新获取仓库列表 |
| 立即同步 | 单仓库 | 行菜单/详情 | 异步触发增量同步；沿用幂等状态 |
| 全量校验 | OCI 单仓库 | 详情次级操作 | 显式绕过缓存；提示耗时和请求成本 |
| 编辑 | 单仓库 | 行菜单/详情 | 沿用现有编辑流程 |
| 删除 | 单仓库 | 行菜单/详情 | 沿用现有确认流程 |
| 诊断 | 单仓库 | 行菜单/详情 | 查看状态、Events 和脱敏错误 |

“立即同步”不等待后端任务完成；页面继续轮询被触发仓库的状态。版本自动刷新属于后续的部署选择页体验优化，不应混入仓库同步动作。

## 实现边界

### Console

预计涉及：

- `packages/shared/src/components/Layouts/` 或现有应用仓库页面布局组件：标题、帮助提示和工具栏层级。
- `packages/console/src/pages/workspaces/containers/Repos/`：仓库列表和详情入口。
- `packages/console/src/pages/workspaces/components/Modals/RepoManagementModal/`：保持表单行为，只做必要的布局适配。
- `packages/shared/src/stores/openpitrix/repo.ts`：只复用现有详情、Events 和同步请求，不新增 API。

### 后端

本期不改后端。现有 API 已提供：

- Repo 列表与详情。
- Events 查询。
- 异步手动同步。
- OCI 全量校验模式。
- 同步统计和脱敏错误。

## 响应式与可访问性

- 桌面端保持列表表格布局；小屏端将每行转换为信息卡片，URL 允许换行。
- 图标按钮必须有 `aria-label` 和键盘焦点状态。
- 异步操作按钮在请求期间禁用并显示状态，不依赖颜色单独表达成功/失败。
- 帮助提示、错误和同步状态应使用可读文本，不只使用颜色或图标。
- 详情抽屉打开后支持 Escape 关闭，焦点不应落到遮罩后面的控件。

## 验收标准

- 首屏默认只出现标题、工具栏和列表，不出现多层固定容器堆叠。
- 添加、刷新、行菜单仍可操作；任何原有操作不会因收纳而丢失。
- 手动同步仍快速返回，列表状态能从排队/同步中收敛到成功或失败。
- OCI 全量校验只对 OCI 仓库显示，HTTPS 仓库不显示该入口。
- 详情能展示现有同步诊断数据和 Events，且不泄露凭据。
- 1280px、1024px 和移动视口下无横向滚动，主要操作可见或可通过明确菜单访问。
- 现有仓库页面相关 TypeScript、格式化、组件测试和 Playwright 回归通过。
