# v4.1.4 OCI 基线重建实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以已验证的 `feature/oci-performance-cache` 为前后端功能基线，选择性吸收官方 v4.1.3 必要改动，形成可测试的 `upgrade/v4.1.4-oci` 候选分支。

**Architecture:** Backend 和 Console 不做整体 merge。每个仓库先从功能基线创建同名候选分支，再按安全、应用生命周期、认证权限、构建和 Console 路由五个波次移植官方补丁。OCI 的既有实现是权威实现；官方首版 OCI 和手动同步提交只用于差异审查和补足测试。

**Tech Stack:** Go、controller-runtime、Helm SDK 3.x、Kubernetes CRD/Helm Chart、React/TypeScript、Jest、GitHub Actions。

**Spec:** `docs/superpowers/specs/2026-09-25-v4.1.4-oci-baseline-design.md`

## Global Constraints

- 新候选分支必须从 `feature/oci-performance-cache` 创建，不能从 `upgrade/v4.1.3-oci` 或旧 `master` 创建。
- Backend 官方源固定为 `v4.1.3` (`3ef3a6bc9`)；Console 官方源固定为 `origin/release-4.1` (`ee28f29f2`)。
- 禁止整体 merge、rebase、force push、改写既有分支或标签。
- 当前 OCI 缓存、凭据、异步手动同步、限流退避和 Console 仓库页面必须保持；上游重叠实现不直接覆盖。
- 依赖、CRD、Helm Chart 生成物只在源代码和 API 定稿后更新一次。
- 所有新增提交使用中文；每个波次都必须先通过测试和 `git diff --check`。
- 未完成测试环境验证前，禁止合入 `master` 或创建正式 `v4.1.4` 标签。
- 本机完整 `go test ./pkg/...` 需要 `KUBEBUILDER_ASSETS` 指向包含 `etcd`、`kube-apiserver` 的 envtest
  二进制目录；Registry 集成测试需要可访问的 Docker Hub 或已配置的镜像代理。缺少它们时只能报告
  环境阻塞，不能把网络超时或缺失二进制误判为源码回归。
- Console 的 Dockerfile 是运行时镜像，预期由 CI 先生成 `dist/server.js`；本地生产构建必须在
  Dockerfile 规定的 Node 14 兼容环境或 CI 中执行，不能以本机 Node 22 的 OpenSSL 失败判断源码。
