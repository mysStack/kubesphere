# KubeSphere v4.3 UI 参考

> 用途：记录 v4.3 Console 的页面结构和交互方向，为当前 v4.1.5/v4.1.x 定制版的 UI 优化提供参考。
>
> 观察环境：`http://10.66.20.25:30880/`，通过浏览器实际登录查看。记录日期：2026-09-28。
>
> 约束：本文是 UI/UX 参考，不代表将 v4.3 的 LuBan 架构、路由或接口整体移植到本项目。

## 1. 首页信息架构

v4.3 首页采用面向任务的四个核心入口，将平台管理能力压缩为清晰的一级卡片：

- 工作空间管理：共享集群资源的租户入口。
- 集群管理：按基础设施管理集群资源。
- 用户与角色：平台级身份和权限入口。
- 扩展中心：扩展安装、升级和管理入口，并展示已安装数量。

首页下方保留“快速访问”区域；没有配置资源时显示空状态和引导，而不是渲染空白区域。

### 可借鉴点

- 先呈现用户要完成的任务，再展开资源细节。
- 将低频的配置入口从主内容中收纳，避免首页堆叠多层导航。
- 用数量和一句话说明帮助用户判断入口价值。
- 空状态必须说明“为什么为空”和“下一步做什么”。

## 2. 页面层级特征

当前 v4.3 页面整体倾向于：

```text
平台壳层
  └─ 一个明确的业务入口
       ├─ 页面标题和一句说明
       ├─ 一个主操作区
       └─ 列表/卡片内容
```

相比当前定制页面常见的：

```text
平台壳层 → 模块卡片 → 帮助横幅 → 搜索工具栏 → 多级标签/筛选 → 列表
```

v4.3 的主要启发是减少同一屏内同时出现的容器层级。帮助信息、筛选项和批量操作应按需要展开，而不是默认全部占据首屏空间。

## 3. 对应用商店/应用仓库页面的建议

### 推荐结构

```text
应用商店管理
  简短说明

  工具栏：搜索 | 刷新 | 设置 | 添加

  应用仓库列表
```

### 建议保留

- 页面标题和一句用途说明。
- 搜索、刷新、设置、添加等高频入口。
- 仓库名称、同步状态、URL、类型和行操作。
- 同步统计和错误信息，但放在状态摘要或详情中。

### 建议合并或收纳

- “如何使用应用仓库”帮助横幅：默认只显示一行，支持折叠；用户关闭后不再占用列表首屏。
- 页面级标签和仓库类型筛选：没有实际筛选需求时不要同时显示多组 Tab。
- 低频设置：放入工具栏设置菜单，不与刷新、添加并列占用同等视觉权重。
- 诊断详情、Events 和完整错误：放入仓库详情/抽屉，不在列表行中展开完整内容。

## 4. 仓库列表的层级控制

列表行只保留“做决定所需”的信息：

```text
名称/图标       状态摘要             URL/类型                         更多
                成功 · 79 个版本
```

状态摘要建议最多展示两行：

- 第一行：成功、同步中、失败或过期。
- 第二行：耗时、有效版本数或简短错误摘要。

以下内容不应默认出现在每一行：

- 完整同步生命周期时间线。
- 所有 OCI 请求/缓存计数。
- 完整错误堆栈和 Kubernetes Events。
- 凭据详情、Token 或 Secret 内容。

这些信息应通过行菜单中的“查看详情/诊断”进入。

## 5. 操作入口优先级

推荐按以下优先级处理操作：

1. 添加仓库：页面主按钮。
2. 刷新列表：工具栏图标按钮。
3. 立即同步：行菜单或仓库详情中的主要操作。
4. 全量校验：OCI 仓库详情中的次级操作，并明确提示耗时和请求成本。
5. 编辑、删除、诊断：行菜单中的低频操作。

“立即同步”和“全量校验”不应与“添加”使用同等视觉权重，也不应在每个列表行中同时显示多个大按钮。

## 6. 当前项目的迁移边界

### 可以在 v4.1.5 发布线采用

- 减少应用仓库页面默认展示的帮助、统计和诊断层级。
- 保留一个清晰的页面主操作：添加仓库。
- 将同步、全量校验、编辑、删除收纳到行菜单或详情页。
- 列表行保留状态摘要，详细同步数据放到详情抽屉。
- 保持现有 OCI/HTTPS API 和异步同步行为不变，只调整展示层级。
- 保持现有权限、Workspace 边界和凭据脱敏逻辑不变。

### 不建议直接移植

- v4.3/LuBan 的整套路由、布局和组件运行时。
- 依赖 v4.2+ 或 v4.3 的新 API、扩展协议和 License 模型。
- 为了视觉一致性重写当前仓库同步 Controller。
- 把企业版扩展中心、Telemetry 或 AI 能力当作当前版本的应用商店需求。

## 7. 建议的后续顺序

1. 先做应用仓库页面层级收敛：帮助横幅、工具栏、列表行和详情抽屉。
2. 再补“同步完成后版本列表自动刷新”，作为部署选择页的体验优化；不新增后端同步机制。
3. 再评估应用版本历史、版本选择、部署记录和回退能力。
4. Gateway API 和 v4.2/v4.3 其他能力按独立阶段评估，不与本次 UI 收敛混做。
